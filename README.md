# OFF MUSIC 2

白いLiquid Glass UI、横画面の3パッド音楽ゲーム。

**[アプリを開く](https://off-music.pinpon-fuuma.workers.dev)**

収録曲：**Play & Pay / OFFSKU**、**Glass Circuit / OFF MUSIC · Suno**。
提供音源・OFFSCREENキャラクターは本人の許可のもとに使用。他社ゲームの
キャラクター・音・ロゴ・譜面は使用しません。

## 遊び方

1. 最初のタップで起動音と小音量のロビーBGMを有効化。
2. 曲・難易度を選択。未ログインならGoogleかゲストを選択。
3. スマホを横向きにして、音符が判定線へ来たら対応するパッドをタップ。
   **丸＝低音、三角＝中音、ひし形＝高音**。PCは **F/J・G/H・D/K**。
4. スコア、コンボ、PERFECT/GREAT/GOOD/MISS、EARLY/LATEとms差を常時表示。
   成績とコンボで背景の熱量とキャラクターの動きが変わります。
5. 完了するとXP、レベル、称号、コンボバッジを獲得。Lv.3/5/8でテーマ解放。
6. 「曲を追加」から20MB・3秒〜10分のMP3/M4A/WAV/MP4等を解析。
   対応コーデックはブラウザによります。追加で30XP、同じファイルは1回。

**本体スピーカーで音ズレを感じる場合：設定→音でタイミングを測る。**
12回の音に合わせてタップし、最初の2回と外れ値を除いた中央値を保存します。
LATEが続くときは判定補正を＋、EARLYは−。補正は入力判定だけに適用されます。
0.75/1/1.25倍速、楽曲・タップ音・BGM音量、振動、動きを減らす設定があります。

## みんなで遊ぶ

Googleログイン→ランキング→グループを作成/招待コードで参加。
「招待」を押すとリンクをコピーできます。配布はご本人が行ってください。
グループ内の表示名を選択でき、メールアドレスは共有されません。

- **曲別**：曲・難易度ごとの自己ベスト。
- **ユーザー総合**：各曲・各難易度の自己ベスト合計。
  重みは かんたん0.6 / ふつう1 / むずかしい1.3 / エキスパート1.6。
- 標準譜面・1倍速の演奏だけを順位へ反映。AIアレンジや速度変更は練習。
- 完了時にサーバーで打鍵記録を再判定し、D1へ保存後WebSocketで他画面へ通知。
  接続が戻ると最新順位を再取得。単なる定期ポーリングの表示ではありません。
- 自分の追加曲を共有したいときは、曲の「AIアレンジ・共有」で共有先を選び、
  配信権を確認して音源と標準解析を共有。参加者だけが再生できます。

ゲストは端末内の記録・レベルを使えます。Googleログインで成長・設定・成績の
クラウド保存、グループ、Workers AIが有効になります。端末だけの音源やゲストの
過去データを、ログイン時に勝手にアップロードしません。

## 音ズレへの対応

旧版にあった発音位置のBPMグリッドへの丸めと固定オフセットを廃止。
22,050Hzへアンチエイリアス付きでリサンプルし、低/中/高3帯域のエネルギー変化を
約3ms単位で検出、局所的なアタックまで遡ります。難易度/AIは実際の発音候補の
採用数を変え、発音時刻は動かしません。音域がパッド種類、推定主音が打音の調律を決めます。
テンポの半拍・倍拍・3連の曖昧さを複数周期の相関で扱います。

`getOutputTimestamp()` の音声出力時計を描画と入力の基準に使用。
入力イベントの発生時刻を用いるので、メインスレッドの処理待ちを遅れとして
加算しません。非対応時はbaseLatency+outputLatencyから推定します。
入力補正と見た目の時計を分け、一時停止・再開でも時計が巻き戻らないようにします。

既知の120BPM・3帯域28音の信号試験：**28/28検出・音域28/28、
中央値1.4ms、95パーセンタイル2.7ms、最大2.9ms**。
これはソフトウェアの発音検出誤差で、スマホ実機の総遅延の測定ではありません。
楽曲解析は推定で、歌声・複雑な伴奏や機器の遅延を完全に除去する保証はありません。
[測定結果](evidence/timing-v2.json)、[調査と計画](V2_PLAN.md)。

## 技術選定と理由

| 技術 | 選定理由 |
| --- | --- |
| React・TypeScript | 選曲、解析、演奏、結果、ログイン、グループを型で接続。 |
| Vite | SSRを要しないゲームを静的ビルドし、解析Workerを別ファイルへ分離。 |
| CSS・Motion | 透明な白いGlass、タイトル・シート・通知・キャラクターの動き。OSとアプリの動き軽減設定を尊重。 |
| Manrope・DM Sans・Noto Sans JP | 大きな英字、数字、読みやすい日本語を揃える。失敗時はシステムフォント。 |
| Canvas 2D | ノーツとヒット演出を毎フレーム描画し、Reactの状態更新と分離。 |
| Web Audio API・OfflineAudioContext | 出力時計への同期、アンチエイリアス付き解析用リサンプル、調律された3種類の打音、独自ファンファーレ。 |
| Web Worker・3帯域DSP・軽量FFT | 音源の発音とエネルギーを端末内で解析し、重い処理中もUIを操作可能に。FFTは主音の推定に使用。 |
| IndexedDB・idb | ローカルの音源Blob、解析、成績、ゲスト成長をリロード後も保持。 |
| Hono・Zod | 軽量APIと、ファイルサイズ・解析・打鍵記録などの入力検証。 |
| Workers Static Assets | 画面・初期曲・キャラクターを静的配信。 |
| Cloudflare D1 | ユーザー、セッション、設定、成績、XP、グループ、順位、プレイチケットを保存。トリガーと一意制約でXPの重複を防止。 |
| Cloudflare R2 | 明示的に共有した音源だけを保存。公開バケットURLは使わず、APIで参加権限を毎回検証。 |
| Durable Objects・WebSocket Hibernation | グループごとの更新を複数画面へ即通知し、待機中のCPU常駐を避ける。 |
| Workers AI | 数値化されたエネルギーから16区間の譜面密度を生成。精密な音符の時刻はDSPが担当。 |
| Google Identity Services・jose | Googleのみの認証とJWT署名・iss・aud・exp・nonceの検証。基本プロフィール以外の権限は不要。 |
| Lucide | 一貫したSVGの操作アイコン。 |
| Vitest・実SQLite | 判定・解析・速度・成長・権限・共有・ランキング・重複再送を再現可能に検証。 |
| Suno | 既存Pro枠内で独自のテスト曲を作成し、提供曲以外のリズムでも確認。 |
| Imagegen | 添付画像の4キャラクターを透明なアトラスへ切り出し。SVGで個別クリップし、CSSで動かす。 |

## 無料範囲を意識した上限

新しい有料プラン・クレジットの購入はしていません。Cloudflareの既存アカウントを使用。

- 共有音源20MiB/曲、20曲/グループ、200MiB/グループ、アプリ全体500MiB。
- グループ全体20、作成者ごと3、メンバー50、ライブ接続100/グループ。
- AIは1人5回/日・全体30回/日、240出力トークン。失敗も利用回数へ含む。
- 曲追加XPは同一ファイルにつき1回、ログイン時は直近24時間で5曲まで。
- プレイ保存は1人100回/直近24時間・全体1000回。端末の曲と結果はIndexedDB。
- 個人クラウド成績は最新300件。演奏チケットは7日で整理、完了後の譜面は解放。

Workers/D1/DO/Workers AIには無料枠があり、R2 Standardは月10GB・書込100万・
読取1000万回までの無料枠があります。既存の他アプリとアカウント枠を共有するため、
アカウント全体の料金が常に0円になる保証ではありません。
[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、
[DO](https://developers.cloudflare.com/durable-objects/platform/pricing/)、
[R2](https://developers.cloudflare.com/r2/pricing/)、
[Workers AI](https://developers.cloudflare.com/workers-ai/platform/pricing/)。2026-10-25確認。

## 開発・配置

Node.js 24以上。

```sh
npm ci
npm run build
npm run db:local
npm run preview
```

`http://localhost:8797`。ホットリロードは別ターミナルで `npm run dev`。

```sh
npm test
node scripts/audit-timing.mjs
npm run build
```

自分のアカウントへ置く場合は `wrangler.jsonc` のaccount_id・D1 ID・R2名・
APP_ORIGIN・GoogleクライアントIDを交換し、D1とR2を作成。
Googleの承認済みJavaScript生成元へ公開URLと必要なlocalhostを追加します。
シークレットは使用しません。`npm run db:remote` → `npm run deploy`。
Durable ObjectはSQLiteクラスのmigrationで作成されます。
